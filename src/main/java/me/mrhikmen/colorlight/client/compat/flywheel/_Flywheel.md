# Flywheel

**What it does:** with the GPU pipeline (Sodium) on, everything Flywheel draws (instanced block entities and entities, Create contraptions, Vanillin) is lit per pixel by ColorLight's coloured light, like the terrain. Without Flywheel nothing changes; without the GPU pipeline Flywheel keeps its own light.

**How it works:**
- Flywheel builds its fragment shaders from text (`assets/<ns>/flywheel/...`). `SourceFileMixin` (`colorlight.compat.mixins.json`) patches the text of every light shader (anything defining `flw_shaderLight`) and of `internal/common.frag` as Flywheel parses it. The light shader keeps its own code (renamed `_cl_flwOrigLight`) and a wrapper runs it, then `cl_flwApply()` from `assets/colorlight/flywheel/colorlight/flw.glsl`; `common.frag` multiplies by the result instead of the lightmap lookup.
- `cl_flwApply()` reads the same light volume as the terrain shader. `flw_vertexPos` is relative to `flw_renderOrigin`, so the position relative to the camera block is `flw_vertexPos + (renderOrigin - cameraBlock)`; the normal comes from screen-space derivatives. Flywheel's own sky light (smooth / embedded) is kept; its block light is replaced by the volume; an instance with block light 15 (full-bright) stays full-bright.
- The world volume's buffers sit on texture units 10..12 (Flywheel uses 0..9) while the engine draws (`EngineImplMixin`, around `render` / `renderCrumbling`). `ContextShaderMixin` points the samplers at them when a program is linked.
- Whether ColorLight is used is the volume header's enabled flag, read in the shader: config switch, shader packs and failures need no recompile, and the shader falls back to Flywheel's light. While no volume exists an all-zero one is bound.
- **Sable sub-levels.** Sable draws block entities / Create contraptions of a sub-level in a Flywheel embedding with a *lighting scene id* (its own copies of the light shaders read `flw_vertexLightingSceneId` / `flw_vertexLightingPos`, the vertex in scene coordinates = plot space minus the plot's centre chunk corner). `SableFlywheelScenes` publishes per scene id the sub-level's `SableLightVolume` window (anchor, first page, plot offset) in a small buffer (`u_CLScenes`, unit 13); the sub-level volume's data / pool go to units 14 / 15. `flw_apply_sable.glsl` (chosen when the light shader mentions the scene id) reads that window the same way the Sable terrain shaders do. Windows are acquired for sub-levels within 160 blocks.
- Mixins live in `cmixin.*`, not under `compat.*`: Sinytra Connector (NeoForge) refuses to load classes from a package that a mixin config owns.
- Nothing is compiled against Flywheel; every mixin is `@Pseudo` with `require = 0`.

**Light of Flywheel objects** (`compat/create/CreateContraptionLightLinker`, option "Light of contraptions", `CREATE_CONTRAPTION_LIGHT`, shown with Create): the blocks of a Create contraption are not in the level, so ColorLight never saw their light sources. Every light-emitting block of a nearby contraption (strongest 24, rescanned when its block count changes and every 40 ticks) becomes a dynamic light that follows the contraption (`toGlobalVector`, updated in 1/4-block steps, floods per tick capped separately for the contraption's own space, the world and other sub-levels, new links first, lights visited in a rotating order so a fast ship cannot starve the later lights, same worker design as `SableLightLinker`). A contraption counts as being on a sub-level when it is within 24 blocks of the plot's block box (pistons / carriages stick out of it). It lights the terrain and, through the shared volume, the contraption's own Flywheel objects. A contraption inside a Sable sub-level is lit in plot space (the ship's objects) and in world space (the terrain). Lights of ordinary block entities and of blocks placed on a ship are static sources and already work. Create is read by reflection.

**Limitations:** the volume covers 31 sections around the camera horizontally (15 vertically), farther away Flywheel objects get no coloured block light. Sub-level objects use the sub-level window (31 sections around the middle of its bounding box, at most 16 sub-levels). The CPU (vertex colour) pipeline does not light Flywheel objects. Written against Flywheel 1.0.7 / Minecraft 1.21.1; not compiled or run (no network in the authoring environment) - please test.
